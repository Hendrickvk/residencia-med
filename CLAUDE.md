# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A study platform for medical residency exams (ENAMED/Revalida) with a question bank, performance dashboard, spaced repetition (SM-2) and timed mock exams, focused on the student's performance and weak spots. Study materials (MediaFire) were removed on 2026-09-14, for now — see `HISTORICO.md`. Database is Postgres on Neon (region `sa-east-1`), connection string in `.streamlit/secrets.toml` (gitignored) for the Streamlit app, or the `DATABASE_URL` env var for everything else (`db.py` falls back to `os.environ` when `st.secrets` isn't available — see `db.py` top of file).

**Hybrid architecture, by deliberate design, not a half-finished migration:**
- Student-facing features (Painel, Praticar, Simulado, Revisão Espaçada, busca) live in a FastAPI + React SPA (`api/`, `frontend/`).
- The admin-only screens (Banco de Questões, Nova Questão, Importar Planilha) live permanently in the original Streamlit app (`app.py`, `ui.py`, `auth.py`) — decided explicitly, not migrating them (see `MIGRACAO.md` §4/§5).
- `db.py` and `repeticao_espacada.py` are the **single source of truth** for all business logic (SM-2 algorithm, filters, streak/ofensiva calculation, dashboard aggregation) and are shared unchanged by both the FastAPI app and the Streamlit app. Never duplicate business logic into the API layer or the frontend — add it to `db.py`/`repeticao_espacada.py` instead.
- Content classification is a fixed two-level taxonomy, `db.TAXONOMIA` (the 5 grandes áreas of the exams > especialidades), seeded by `init_db()`. Questions and subtopicos carry `area_id` (the grande área — what the Painel aggregates) plus `especialidade_id`. The spreadsheet importer resolves free-text names with `db.classificar_nome_area` / `resolver_area_especialidade` and reports unknown names as errors — never insert an `areas` row from an imported name (that's how MediaFire folders like "Aprenda Nefro" used to show up as areas). Below each especialidade there is a fixed list of temas, `db.TEMAS` (grouped from the Revalida matrix, Portaria Inep 540/2020, art. 7º), seeded into `subtopicos` by `init_db()`; the same rule applies (`db.obter_tema` resolves names, unknown temas are errors). The 44 old MediaFire subtopicos (with `origem`) stay in the table but `db.listar_temas` hides them. Each question also has a `tipo_pergunta` (`db.TIPOS_PERGUNTA`: Diagnóstico, Exames, Conduta, Conceitos), given by what its alternatives are — the most advanced step when it asks for several (Conduta > Exames > Diagnóstico); `scripts/classificar_tipos.py` applies a classification JSON with a dry run and backup; the Streamlit form and the spreadsheet importer both require it, so no new question can land untyped (a question without `tipo_pergunta` is invisible to the Praticar filter and to the Painel's "Por tipo de pergunta"). Rollout is phased — status in `HISTORICO.md` (Pendências).

Read `MIGRACAO.md` (migration plan, phase-by-phase decisions, the real function→endpoint contract) and `DEPLOY.md` (production runbook, checklist of what's actually deployed) before making structural changes to the API or touching the production server. `HISTORICO.md` is the condensed history of decisions still in force ("why was this built this way"), the pending work, and the Streamlit admin CSS gotchas — check it before re-deriving a past decision. Superseded history exists only in git (the old `contextoconversaclaude.txt`).

The app is branded **Conduta**, but internal identifiers (systemd user `residenciamed`, service names, session cookie, demo e-mail, paths) deliberately kept the old name — renaming them breaks the deploy and open sessions.

## Commands

### Backend (FastAPI)
```bash
pip install -r requirements.txt
uvicorn api.main:app --reload            # dev server, http://localhost:8000
pytest                                     # runs everything in tests/ (pytest.ini: testpaths = tests)
pytest tests/test_sm2.py                   # single file
pytest tests/test_sm2.py::test_nome        # single test
```
If `uvicorn --reload` keeps serving old routes after edits (has happened on this Windows machine), stop both uvicorn processes and start it again. `streamlit run` never picks up `db.py`/`ui.py` changes on refresh — restart it.
**There is no separate test database** — tests run directly against the production Neon Postgres (same `DATABASE_URL`/secrets as prod). Fixtures in `tests/conftest.py` create uuid-suffixed data (`pytest_<uuid>@teste.local`, `__pytest_area_<uuid>`) and clean up via `ON DELETE CASCADE` in teardown. Any new fixture must follow this pattern — never write a fixture without teardown, and never reuse real user data. Production also holds two non-real accounts: `demo@residenciamed.com` (fake history from `scripts/seed_demo_user.py`, plus spaced-repetition history from `scripts/seed_demo_revisao.py`; both idempotent) and `qa.claude@residenciamed.local` for browser QA.

```bash
streamlit run app.py                      # http://localhost:8501, needs .streamlit/secrets.toml
```
Running this via a sandboxed/isolated shell (no outbound network) hangs forever inside `db.init_db()` with no visible error — if `streamlit run` seems to hang, check network isolation before assuming a code bug (`timeout 8 bash -c "cat < /dev/tcp/<host>/<port>"` against the DB host is a quick diagnostic).

## Architecture

### `api/` (FastAPI)
- `main.py` — app + lifespan hook (calls `db.init_db()`) + CORS via `CORS_ORIGENS` env var.
- `security.py` — auth is JWT in an **httpOnly cookie**, not bearer+refresh. The token carries a `tv` claim
(`usuarios.token_version`) that `deps.usuario_atual` compares on every request — that is what makes
logout and password reset revoke a *stolen* token, since the JWT itself is stateless and lives 12 h.
Anything that should end a session bumps the column (`db.invalidar_sessoes`); a token with no `tv` is
rejected, so shipping a change to this logs everyone out once, by design. `COOKIE_SECURE` is env-controlled and defaults to `false` (must be `true` once served over real HTTPS — see Deployment below).
- Password reset (`POST /auth/senha/esqueci` → e-mail → `POST /auth/senha/redefinir`, table `senha_tokens`, page `/senha/:token`). Three rules that are security, not style, and must not be "simplified": **the request endpoint always answers `200 {"ok": true}`** whether or not the account exists (anything else turns it into an oracle for who has an account here, so nothing in it raises — not a missing account, not a failed send, not the rate limit); **the DB stores only the token's SHA-256**, so read access to Postgres redeems nothing; and redeeming **burns every outstanding token of that user** in the same transaction. Tokens last 60 min, are single use, and a user gets 3 requests per 15 min (`db.contar_tokens_recentes`). Invalid, expired and already-used tokens all return the same 400 message. Sending goes through `api/email.py` (Brevo's HTTP API — `httpx` was already a dependency, and Brevo verifies a *sender address*, which the project can have without a domain); with no `BREVO_API_KEY` it logs the would-be e-mail (link included) and returns False, which is the dev path for copying the link out of the server log. Since 2026-09-22 the domain is authenticated at Brevo (DKIM + DMARC on `qualaconduta.com.br`), so mail goes out as `acesso@qualaconduta.com.br`; before that Brevo rewrote the `From:` of a freemail address to `@…brevosend.com`, because an unauthenticated freemail sender fails the recipient's DMARC check. `tests/test_senha.py` pins the three rules above.
- **Confirmation of e-mail** (since 2026-09-23). Signup is open to anyone on purpose; what makes an
  account cost something is having to receive an e-mail. `usuarios.email_confirmado_em` + table
  `confirmacao_tokens` — **a separate table from `senha_tokens`, never a `tipo` column on it**: one
  forgotten filter would make a confirmation token work as a password-reset token. Same rules as the
  password flow (SHA-256 only, single use, redeeming burns the siblings, one message for
  missing/expired/used), 48 h instead of 60 min. What it gates is the *content*, not the door:
  `api.deps.usuario_confirmado` (403, not 401 — she is logged in, something else is missing) guards
  `/praticar/sessao` and simulado creation only, so someone who never got the e-mail can still log in
  and ask for another link. Confirming does not create a session — that would make the link a magic
  link. Accounts that predate the migration were backfilled as confirmed. Any new test that creates an
  account through `/auth/signup` and then asks for content must call `confirmar_email()` from
  `tests/conftest.py`, and must draw its e-mail *before* the call so the teardown can delete by e-mail
  (an endpoint that raises after inserting the row leaks an account into production otherwise — it did).
- `api/email_modelo.py` — the HTML e-mail, table-based and inline-styled, in the Triagem system
  (paper `--ground`, card with a 1px border, ink button, the five triage bars as the brand mark). Both
  transactional e-mails go through it; `enviar_email` sends text **and** HTML, because a text-only
  client and the spam filter both need the text part. E-mail clients don't load Google Fonts, so
  Archivo is only the first entry of a stack ending in Arial.
- `deps.py` — `usuario_atual`, `eh_admin` (reads `db.emails_admin()`: `ADMIN_EMAILS` from `.streamlit/secrets.toml` or the env var, comma-separated). **No admin e-mail and no JWT secret belongs in the code** — both were hardcoded until 2026-09-20 in a public repo. With no config, nobody is admin and `security.py` signs sessions with a random per-process secret (loud warning in the log, sessions die on restart); that is the safe side of the failure, and the old fixed default meant anyone could forge a session cookie for any account if the variable were missing in production. `/auth/login` allows `MAX_TENTATIVAS_LOGIN` failures per (IP, e-mail) in a 5-minute window, counted for accounts that do not exist too (otherwise the limit itself tells you who has an account); `tests/test_login_limite.py` pins it.
- `schemas.py` — Pydantic models. `CredenciaisIn.email` is plain `str` + a custom validator, not `EmailStr`, because `email-validator` rejects `.local`/reserved TLDs used by test fixtures.
- `serialize.py` — `questao_publica()` must wrap every question row returned by any endpoint: strips `imagem`/`imagem_mime` (Postgres BYTEA, not JSON-serializable) into a `tem_imagem` bool, and parses the `alternativas` column (stored as a TEXT/JSON string) into an object.
- `routers/` — one file per resource. **Central architectural decision**: `GET /praticar/sessao` returns the *entire* question batch for a session with gabarito+explicação already embedded (via `serialize`), not one question at a time. This is what makes instant client-side feedback possible without a round-trip per answer — don't "optimize" this into a paginated/lazy endpoint. `GET /praticar/contagem` takes the same filters minus `quantidade` and answers how many cases the Configurador's current selection has (it drives the live count and disables the start button at zero). It counts through the same `db.ids_questoes_filtro_pratica` the session uses and returns `len()` — a `count(*)` of its own would duplicate the WHERE and drift from the session on the first filter change; the id list is cheap because the whole bank is 1074 rows. `tests/test_api_smoke.py` pins the contract (count == what the session delivers when `quantidade` exceeds it). Since 2026-09-23 the session endpoint also
spends a **daily per-account quota** (`db.TETO_DIARIO_PRATICA` = 500 cases, table `cota_pratica`,
`db.consumir_cota_pratica`), because embedding the gabarito is what makes 6 requests enough to
take the whole bank; it charges per case actually delivered, after the cut, and answers 429 when
the day is spent. `/praticar/contagem` is deliberately **not** capped — it returns no content, and
capping it would make the Configurador's live count lie about the bank.
- `GET /questoes/{id}/imagem` answers with `ETag` (sha256 of the bytes) and `Cache-Control: private, max-age=86400`, and returns 304 on `If-None-Match`. The figure is the heaviest thing the platform serves (~300 KB) and the least likely to change, and spaced repetition brings the same question back many times — without this the phone re-downloaded it on every appearance. `private` because the route needs a session: the cache belongs to her browser, not to a proxy on the way. The ETag is content-based, so `scripts/substituir_imagem.py` invalidates it on the next revalidation instead of waiting out the 24 h. `tests/test_imagem_cache.py` pins all of it.
- `POST /respostas` is fire-and-forget from the frontend's perspective — the UI never waits on it to show correct/incorrect.
- The official-edition simulado (`POST /simulados/oficial`, "Prova oficial" tab), the edition list and the banca filter read `questoes_provas` (question id, banca, edicao like `"2025/1"`, numero_prova = number in the INEP booklet). A question can belong to more than one booklet: Revalida 2025/2 and ENAMED 2025 applied the same questions 1–50, stored once and linked to both. `questoes.edicao`/`questoes.numero_prova` still hold the primary booklet only, because the server's older code reads them; `init_db()` backfilled the table from them when it was created. Any new import of an official exam must insert its `questoes_provas` rows (and fill the columns), or the edition won't be listed or will come out of order.

### `frontend/` (Vite + React 19 + TS + Tailwind v3)
- Tailwind v3 was an explicit choice over v4. The visual system is "Triagem" — read `DESIGN_TRIAGEM.md` before touching UI. Tokens are mapped in `tailwind.config.js` / `src/styles/theme.css`; dark mode via a `.dark` class on `<html>`. The five triage colors (`t1`–`t5`) only ever encode a triage level (`src/lib/triagem.ts`), never decoration, and primary buttons are ink (`bg-ink`), not a brand color. `REDESIGN.md` ("laudo clínico") now only governs the Streamlit admin screens.
- Tailwind only generates classes it finds written out literally: per-level classes are precomputed in `CLASSES_NIVEL` (`src/lib/triagem.ts`) — never build class names like `` `bg-t${n}` `` at runtime.
- Layout is a top bar with tabs (no side rail). Session screens (Praticar session, Simulado in progress, Revisão) render `<BarraFoco>` (`src/lib/foco.tsx`), which portals the session's own bar into the top bar and hides the tabs, so the shell never needs to know which session is running.
- TanStack Query (React Query) for server state. **Known pitfall already hit twice**: a hook with `staleTime: Infinity` reused across two different screens under the *same* queryKey leaks stale data from one screen's phase into another's (happened with `useItensSimulado` between "em andamento" and "resultado"). Before setting a long/infinite `staleTime`, confirm the queryKey is exclusive to one screen/phase, or invalidate explicitly before navigating (see `EmAndamento.tsx`).
- React Router paths are stable keys, deliberately decoupled from the nav label shown in the menu (same lesson learned the hard way on the Streamlit side, where the label used to double as the routing key).
- **Flashcards** (`/baralhos`, `api/routers/cartoes.py`, `lib/cartoes.ts`): the student's own cards,
  pasta > baralho > cartão. They run on **the same SM-2 as the questions** —
  `repeticao_espacada.calcular_proximo_estado` is pure, so `avaliar_cartao` reuses it and only picks
  where the state lives (`revisao_cartao`, a separate table because `revisao` is FK'd to `questoes`).
  Never write a second scheduling algorithm. The two review queues are deliberately separate for now
  (merging is a UNION, not a new algorithm). `usuario_id` is denormalised onto baralho and cartão so
  every query scopes by owner in the WHERE — that is what stops someone fetching another account's
  deck by id, and `tests/test_cartoes.py` pins it endpoint by endpoint. The 12 folder colours are
  **another palette outside the triage scale**, for the same reason as the avatar colour, and each has
  a `-soft` veil (deck band) and a `-on` text colour, measured at 4.5:1 for the folder banner, which is
  filled with the full colour — a hardcoded white fails on cyan, rose, lavender, orchid and turquoise.
  Retiring a colour key requires a migration in `init_db` (green and gold were dropped in 2026-09-23
  because vivid versions would read as triage levels), or existing folders silently fall back to the
  default. Visually the decks follow the "real deck" direction the
  user picked from three prototypes: the edges of the cards behind show above the tile, and **that stack
  is only drawn when the deck has more than one card** — the metaphor has to be honest. Grade buttons are
  coloured pills that must use `bg-tN text-tN-on`; a hardcoded white breaks contrast on t2/t3 in light
  mode. Counting cards goes through `plural()` in `lib/cartoes.ts`: naive interpolation writes "cartãos".
- **`/perfil`** (`pages/perfil/`) — the account page: identity, exam date, marked questions. It is
  deliberately outside `NAV` (the account is not a study tab; the way in is the account menu). The
  **marked list returns no gabarito, alternativas or explicação** (`db.resumo_questoes_marcadas`) and
  that is a security boundary, not a payload choice: question ids are sequential, so marking all 1074
  and fetching the list once would drain the bank around the `/praticar/sessao` daily cap. Reviewing
  them goes through the `apenas_marcadas` filter on that same capped endpoint.
  `tests/test_pagina_perfil.py` fails if the list ever starts returning answers.
- **Profile identity** (`src/lib/perfil.ts`, `components/Perfil.tsx`): a display name and an avatar
  colour, per account. The six colours are a **separate palette from the triage scale** and must stay
  that way — t1–t5 encode performance, so a green avatar would read as "doing well"; they also do not
  change with the theme, because it is the person's colour. The DB stores the **key**, validated
  against `db.CORES_PERFIL` (a colour arriving from the client becomes CSS), and the Tailwind classes
  are written out literally, never built as `bg-perfil-${cor}`. An empty name goes back to NULL and the
  UI falls back to the e-mail. The **photo** lives in `fotos_perfil`, a table of its own and never a
  column on `usuarios` — `obter_usuario` does `SELECT *` on every authenticated request, so a BYTEA
  there would ship the photo from Postgres on every API call. `usuarios.foto_versao` (the content sha)
  is what `/me` exposes and what goes in the image URL, so a new photo is a new URL and the response
  can be cached `immutable` for a year. Resizing happens in the browser (`lib/foto.ts`, 256px square,
  JPEG); the server checks what the client cannot be trusted for — decoded byte size and the file
  signature against the declared type. **SVG is not an accepted type**, and that is not an oversight:
  it is XML with script in it, served back from our own origin.
- **"O que mudou"** (`src/lib/novidades.ts` + `components/Novidades.tsx`). The changelog the student
  sees: entries live in the **front-end list**, newest first, and the server deliberately doesn't know
  them — it only remembers the id of the last entry each account read (`usuarios.novidades_vistas`,
  `PATCH /me/novidades`). In the DB and not `localStorage` because she studies on a phone and a laptop
  and the box would appear twice. **A published entry's `id` must never change** — changing it reopens
  the box for everyone. It opens by itself once, only on `/painel` (never over a case mid-session), and
  stays reachable from the account menu. `visto` null, or an id no longer in the list, shows only the
  most recent entry, never the whole history. Write each line as what she gains, not what was
  implemented, and leave out anything she can't see on screen.
- `src/lib/respostasQueue.ts` — module-level retry queue with backoff for answer submissions; invalidates the `["me"]` query on success so the topbar streak/counters update (they don't otherwise, since the queue lives outside React).
- Admin-only routes (`ACERVO` in `src/lib/nav.ts`) render `PermaneceNoStreamlit.tsx` (a placeholder linking to `VITE_STREAMLIT_URL`) instead of a real page — this is intentional per the Fase 7 decision, not a stub to fill in. Links to them appear only in the account menu, and only for `is_admin`.
- **A failed query is not an empty screen.** `components/EstadoFalha.tsx` (solid border, "Tentar de novo") exists because the Painel, the Revisão and the Praticar session all treated `data === undefined` as "you have nothing": on a dropped connection the app told a student with three weeks of history "ainda não há respostas para montar a sua triagem" and one with 30 due cases "nenhuma revisão vencida hoje". Any screen whose main query can fail must branch on `isError` before its empty state — measured on 2026-09-19: 40 `useQuery` call sites, 3 handled `isError`. Sub-cards that only render inside a loaded page don't need it. **Three states, in this order**: data (even stale) wins and stays on screen when a refetch fails (the rule `RequireAuth` already followed); then `isPaused`; then `isError`. `isPaused` is not a detail — in the default `networkMode: "online"`, query-core's retryer pauses instead of failing whenever `focusManager.isFocused()` is false or the browser is offline (`retryer.js`: `canContinue()`), which is exactly the phone-in-a-tunnel case. While paused, **`refetch()` is a no-op** and the query resumes by itself on focus/online — so that state gets a "carrega sozinho" message and *no* button. Checked live, not by reading: a failing fetch in a background tab paused after one attempt, and came back on its own when the tab became visible.
- `components/BarreiraErro.tsx` wraps the whole app in `main.tsx`: before it, a throw anywhere left a blank page with no way out and no console at hand on a phone. React has no hook for this — it is a class on purpose. It prints `componentStack` to the console (front-end errors are not shipped anywhere) and shows the error message only in DEV.
- The theme is applied in `main.tsx` (`aplicarTema(temaInicial())`), not only in `AppShell`: `/login` and `/senha/:token` render outside the shell and used to show up light for a dark-theme user. `aplicarTema` also copies `--ground` into `<meta name="theme-color">`, because the mobile address bar is painted by that meta and not by the CSS.
- `lib/sessaoSalva.ts` keeps one practice session in `localStorage` (12 h, keyed by e-mail because this browser logs into more than one account) so closing the tab mid-session doesn't lose it — `pages/praticar/index.tsx` offers "Retomar"/"Descartar" above the Configurador. **The whole question batch is stored, not just the ids**, because `/praticar/sessao` draws at random and asking again with the same filters returns different questions. Answers already given were never at risk (`respostasQueue` sends them as she answers); what was lost was her place.
- Icons and `manifest.webmanifest` live in `frontend/public/` and are derived from the brand symbol (see `DESIGN_TRIAGEM.md` §3). A `favicon.svg` sitting in `public/` is **not** discovered on its own — the browser only asks for `/favicon.ico`, so the `<link rel="icon">` in `index.html` is what makes the tab icon exist.
- `frontend/.env.production` has no secrets (just `VITE_API_URL`/`VITE_STREAMLIT_URL`) but is easy to accidentally gitignore: the root `.gitignore` pattern for the backend's `.env.production` must stay anchored to the repo root (`/.env.production`), or it will also match and silently exclude the frontend one.

### Postgres specifics
- `LIKE` is case-sensitive in Postgres (unlike SQLite, which earlier docs incorrectly assumed). Any free-text filter in `db.py` must use `ILIKE`.
- Postgres doesn't auto-index foreign keys — indexes on `respostas.usuario_id`, `respostas.questao_id`, `questoes.area_id`, `questoes.banca` are created explicitly in `init_db()`.
- `revisao.proxima_revisao` is a real `TIMESTAMP` (migrated from `TEXT`/date-only), so short "review again in 10 minutes" scheduling works for real — don't regress this back to date-only comparisons.
- Neon drops connections when its compute suspends for inactivity, and psycopg2 only notices on the next query. `db.get_conn()` therefore pings (`SELECT 1`) any pooled connection idle for more than 30 s and replaces it if dead — without that, the first request after a quiet period failed with "connection already closed". Keep that check if you touch the pool; `tests/test_conexao.py` covers it.
- `questoes.area_id` is `ON DELETE CASCADE` to `areas`: deleting an area silently deletes its questions (and its rows in `materiais`, a table with no code since 2026-09-14 that still holds 1646 rows, like the `subtopicos.origem` column). Always verify an area is empty first.
- Bulk changes to production data (imports, reclassification, text fixes): run `python scripts/backup_banco.py` first (full `pg_dump` into `backups/db/`, verified by counting the `questoes` rows inside the file), then write a script that runs everything in one transaction, prints a summary and rolls back unless given an explicit apply flag; save a JSON backup of the touched rows; apply only after the user confirms. Update rows in place (never delete and re-insert questions) — `respostas` and `revisao` reference question ids. The per-operation JSON backups only restore the rows they touched; `backup_banco.py` is the only thing that reconstructs the bank — 1074 questions and 79 hand-cropped images that exist nowhere else. `backups/` is gitignored, so those dumps live only on this machine — `--espelho DIR` (or `$BACKUP_ESPELHO`) mirrors the verified dump out, and `--empurrar` pushes that folder to a **private** git repo (the dump carries every account's e-mail and password hash), replacing its history with a single commit each time so 24 MB snapshots don't accumulate forever. The destination is `Hendrickvk/conduta-backups` (private), `$BACKUP_ESPELHO` is already set on this machine, and `scripts/backup_semanal.cmd` is the wrapper the weekly scheduled task calls ("Conduta - backup semanal", Sundays 20:00, created 2026-09-23 with `-StartWhenAvailable` so a laptop that is off does not silently skip the week) — it `cd`s to the repo root because `db.py` finds `.streamlit/secrets.toml` relative to the working directory, and it appends to `backups/backup_semanal.log`, the only sign that a weekly backup has stopped happening. Pushing the dump anywhere is a **user** action: the safety classifier blocks the tool from doing it, and rightly so — the dump carries every account's e-mail and password hash. **Restoring was verified once, on 2026-09-23**, and that is the half nobody had tested: `CREATE DATABASE`
on a **direct** Neon connection (drop the `-pooler`; `CREATE DATABASE` runs through neither the pooler nor a
transaction), `pg_restore --no-owner --no-privileges`, then a table-by-table count against production — 13
tables, no divergence, all 79 figures intact, 25 seconds. Redo that check after any change to the dump
pipeline; a backup nobody restored is an assumption, not a backup.

### Question bank content
- One image per question, stored in the DB (`questoes.imagem` BYTEA + `imagem_mime`). Two figures → stack them into a single PNG.
- **Importing an official INEP exam** (done for Revalida 2021 and 2022-2 through 2026-1, plus ENAMED 2025). `scripts/importar_prova.py` does the writing half: it takes the assembled JSON, resolves área/especialidade/tema against the taxonomy and refuses unknown names, rejects duplicates (banca + ano + start of statement) and repeated booklet numbers, runs a dry run by default and, with `--aplicar`, writes questions and their `questoes_provas` rows in one transaction with a JSON backup of the inserted ids. The reading half is still per-booklet work:
  - Links: INEP's main page loads them by script, but each year tab (`https://www.gov.br/inep/pt-br/areas-de-atuacao/avaliacao-e-exames-educacionais/revalida/provas-e-gabaritos/{ano}`) has the PDF links in plain HTML — `curl` it and grep for `download.inep.gov.br`. Names changed over time: up to 2025/1, `{ed}_PV_objetiva_regular.pdf` and `{ed}_GB_objetiva_definitivo.pdf` with an underscore (`2025_1_…`; 2022-2 is `2022-2_PV_objetiva.pdf`); from 2025/2 on, `{ed}_caderno_1_….pdf` and `{ed}_gabarito_definitivo_caderno1.pdf` (2025/2's key is `2025_2_gabarito_caderno_1.pdf`, definitive despite the name). Always use caderno 1 and the definitive answer key.
  - If a booklet shares questions with one already in the bank (Revalida 2025/2 questions 1–50 are ENAMED 2025's), add a `questoes_provas` row to the existing question instead of inserting a copy.
  - The booklet has two columns: filter pdfplumber chars by x-center relative to the page middle before `extract_text()`, or the columns interleave. Tables flatten into one line and subscripts detach — rewrite those statements in prose. The perception questionnaire after Q100 can stick to the last question.
  - Figures: `page.images` bboxes (ignore the small repeated header logos ~135×17/145×40), `page.crop(bbox).to_image(resolution=200)`, and look at the PNG before saving — wrong-question crops have happened, as have crops that cut a legend in half (Revalida 2021 Q41) or bleed a strip of the *neighbouring* figure into the right edge (UNICAMP 2023 Q7: 12 px of the next question's histology). Check all four edges, not just the subject. But before re-cropping because a label looks cut, re-crop the page with a few points of slack and compare: Revalida 2022/2 Q27's film reads "OSTÁTICO" in the corner and the truncation turned out to be in the raster the booklet itself published, so the stored image was faithful and there was nothing to replace. A stem that never mentions its own figure is normal, not a lost phrase: 5 of the bank's 79 figure questions are like that, because the booklets place the image without an inline marker (checked 2026-09-17).
  - ENAMED 2025's PDF font (Calibri) has no ToUnicode map, so pdfplumber returns `(cid:N)`; the CIDs are Calibri glyph ids — decode by inverting the cmap of `C:\Windows\Fonts\calibri*.ttf` with fontTools (ligatures included). Its questionnaire reuses "QUESTÃO 1..9": take only the first occurrence of each number.
  - Leave out annulled questions and ones that depend on third-party images. Classify area, especialidade, tema and `tipo_pergunta` by the question's content, not booklet order. Fill `banca`, `ano`, `edicao`, `numero_prova`.
  - Explanations are written from scratch. Before saving, check each one argues for the official answer letter (caught one written for the wrong letter), no table debris remains, and images exist. Dedupe by banca + ano + start of statement. After writing a batch, run `python scripts/auditar_explicacoes.py --banca X --edicao Y` and read what it flags — see the caveats below.

### Reviewing the explanations (done — all 1074 read, 51 rewritten)
The explanations were all written here, so nobody independent had ever read them. The review ran from 2026-09-16 to 2026-09-18 and covered every edition in the bank — USP 2026 (10 defects in 113), ENAMED 2025 (4/90), Revalida 2026/1 (0/99), 2025/2 (4/93, of which 43 questions were already covered by the ENAMED pass — they are the same questions), UNICAMP 2023 (5/79), Revalida 2025/1 (1/97), 2024/2 (9/94), 2024/1 (5/95), 2023/2 (2/90), 2023/1 (5/93), 2022/2 (5/86) and 2021 (1/88). Per-question status and notes live in `backups/revisao_explicacoes.json` (gitignored) and show up at the top of the Streamlit **Revisar explicações** screen; every question is `ok` with nothing pending. Tools: `scripts/dump_explicacoes.py <banca> <edicao> [--de N --ate N]` to read them, `scripts/corrigir_explicacoes.py <json>` to rewrite (dry run, backup, `--aplicar`), `scripts/substituir_imagem.py` for figures. **A newly imported edition still has to be read the same way — the lessons below are what to look for, and re-reading the whole bank question by question is finished: scan for a pattern instead (see the last two bullets).**

What the review actually found, and what it means for where to look next:
- **There are two separate risk factors, not one.** Figures are the first (below). The second, found in Revalida 2024/2 — 9 defects in 94, the worst rate of any edition, with a single figure in the whole booklet — is an explanation that states a **formula, a dose, a numeric cutoff or a legal article**. Those are the checkable claims, so they are where a wrong one survives, and they are what the student memorises. Two of the nine were outright wrong (Parkland's 4 mL/kg/%TBSA where the answer key only works with ATLS 10th's 2 mL, so the cited formula led to the wrong letter; and "plano de saúde" and "comissão de PCCS" declared not to be requirements of Lei 8.142 when both are in its article 4). `scripts/auditar_numeros.py` lists every such claim in the bank on one screen — run it on a freshly written edition. Measured on the whole bank on 2026-09-17: 2 formula sentences, 18 doses per kg and 19 legal references, of which exactly those two were wrong. The older editions kept confirming the pattern in claims the scan can't see, because they are cutoffs rather than formulas: Revalida 2023/1 called a sepsis at 36 hours of life "late-onset" (it is early) and diagnosed acute pancreatitis on enzymes at about 2× the upper limit when the criterion is 3×; Revalida 2022/2 refuted a sterilisation alternative on the age alone when what it really gets wrong is that the requirements are alternative, not cumulative.
- **Defects cluster in the edition with the most image-dependent questions, not in the batch written fastest.** USP 2026 yielded 10 problems in 113; Revalida 2026/1, written the same day in the same session, yielded 0 in 99. Four of the USP ones were explanations describing an image wrongly. So when reviewing, prioritise questions with figures and alternative-images, and always open the image instead of trusting the text.
- **The cheap test for a figure question: if the explanation would still read as valid with the figure deleted, it never read the figure.** That is the whole defect in the worst one found in Revalida 2022/2 (Q45, id 422): the stem says "conforme os dados dos gráficos apresentados" and the explanation argued from the racial disparity the Ministry's bulletins documented — true, and not the answer, which only follows from comparing the two charts (the white share falls from 65.1% of hospitalisations to 56.6% of deaths while the parda share rises from 26.9% to 34.6%). The same test caught Revalida 2022/2 Q27 and 2023/1 Q77, where the whole question is a radiograph the explanation never described. Watch for the naive reading too: in that pie chart the biggest slice of deaths is the white one, so a student who reads only the second figure concludes the opposite of the gabarito — say so.
- **The writing vintage predicts defects better than the date.** Revalida 2021 — the last edition imported, and the one whose explanations are the longest, name the mechanism and close with a practical consequence — gave 1 defect in 88. Revalida 2024/2, whose explanations are short and assertive and state formulas, doses and legal articles flatly, gave 9 in 94 with a single figure in the booklet. Two ends of one measure: the terse confident style is the risk factor, the style that explains the mechanism defends itself. Write new explanations imitating the 2021 batch.
- The one serious defect found (USP Q22) argued for a different letter than the gabarito **without naming any letter**, so the "does it cite the right letter" check that this file used to recommend did not catch it. `scripts/auditar_explicacoes.py` does catch it, but measured on the whole bank it returns ~26 suspicions that are almost all synonym false positives ("soro fisiológico" vs "cloreto de sódio 0,9%"). Use it on a freshly written edition, never as an audit of the bank, and never as evidence that the rest is fine — it cannot see wrong clinical reasoning that defends the right letter, which is most of what human reading finds.
- **Never write a bare `(A)` for anything that is not the alternative.** Revalida 2025/1 Q77 said "a primeira prioridade é a via aérea (A)" meaning the A of ABCDE, and two sentences later used "(A)" for alternative A — which was the wrong one. Same failure mode as USP Q22: the text reads as defending another letter. The letter in parentheses is reserved for the alternative; spell out anything else ("o 'A' da sequência ABCDE").
- **The bank contradicting itself is the most productive thing to look for.** Every defect class found so far shows up as two explanations of the same topic disagreeing: the WHO eligibility caveat present in three contraception-in-lupus questions and missing in a fourth; the 2 mL burn formula right in Revalida 2026/1 Q60 and wrong in 2024/2 Q17; "start mammography 10 years before the relative's age" taught in 2025/1 Q59 and contradicted by "sem fator de risco adicional" in 2024/2 Q84; the ASC-US interval stratified by age in 2025/2 Q68 and flat in 2024/2 Q34. When you fix one, grep the bank for its siblings.
- **When a defect turns out to be a pattern, scan for it instead of waiting to meet it again.** The missing WHO-eligibility caveat on hormonal contraception in lupus appeared in three separate editions. One query over the bank (questions mentioning lupus/antiphospholipid/thrombophilia whose alternatives are contraceptive methods, checking whether the explanation mentions "categoria" or "elegibilidade") proved the remaining 6 already had it and the UNICAMP one was the last — the pattern was closed, not open. Cheap, and it ends the doubt.
- **A second pass over already-reviewed questions finds gaps, not defects.** The 43 Revalida 2025/2 questions shared with ENAMED 2025 had all been marked ok; re-reading them surfaced 3 explanations worth improving (a missing WHO-eligibility caveat, an unused argument in a distractor, a wrong Sporothrix species) and no wrong answer. So a re-read is worth doing when a sibling question got a correction the other one did not — not as a general audit.
- Rewrites go in as UPDATEs with the previous text backed up; never delete and re-insert.

### Deployment

Production runs on Oracle Cloud Free Tier (São Paulo) and is **live over HTTPS** since 2026-09-22 at its own domain: `https://qualaconduta.com.br` (student app, API under `/api`) and `https://admin.qualaconduta.com.br` (the Streamlit admin screens). The old free `conduta.duckdns.org` still answers, as a redirect, so shared links keep working. `DEPLOY.md` is the runbook and the checklist of what is actually deployed; it was rewritten on 2026-09-22 and is current. `COOKIE_SECURE=true`, `CORS_ORIGENS=https://qualaconduta.com.br`, port 8080 closed (the admin no longer uses it), and the session cookie verified in production as `HttpOnly; Secure; SameSite=lax`.

SSH from this machine works (`ssh residencia-med`, key `~/.ssh/conduta-oracle`, authorized on 2026-09-22). Keep remote commands short — long composite SSH commands have tripped the safety classifier. The code on the server belongs to the `residenciamed` user, so every `git` and `pip` there runs under `sudo -u residenciamed` (running as `ubuntu` gives "dubious ownership").

**The frontend is built here and shipped, not built on the server**: the instance has 954 MB and no swap, so `npm install` + build there risks an OOM. `DEPLOY.md` §8 has the tar/scp/atomic-swap commands, and `dist.antigo` stays on the server for rollback. This works because `frontend/.env.production` uses the relative `VITE_API_URL=/api`, so one bundle serves both http and https.

What still needs a human: rotating the published `demo@residenciamed.com` password, a real browser login over https, and clearing the leftover 8080 ingress rule in Oracle's Security List (see `HISTORICO.md` Pendências).

## Known constraints (not stylistic preferences — don't relax these)

- Never copy questions or explanations from paid competitor platforms (Estratégia MED, Medcof, etc.) — official free sources (INEP) or original content only.
- Clinical explanations authored for questions must not be labeled as AI-generated — explicit user decision, don't reintroduce an "AI-generated" marker without asking first.
- Never type a password into a login/signup field via browser automation, including for test accounts — the user always logs in manually in an already-open tab.
- Never open a firewall port or Security List rule to `0.0.0.0/0` for a service without HTTPS — restrict it to the admin's /32 or use an SSH tunnel. If the safety classifier blocks such a change, the block is right.
- `git commit` / `git push` only when the user asks.
- **Never put a credential, an admin e-mail or a signing secret in the code, not even as a "dev" default.** The repository is public: `scripts/seed_demo_user.py` shipped `demo@residenciamed.com`'s real password, and it still worked on the production account when found on 2026-09-20 — any reader could log in and, being authenticated, pull all 1074 questions with gabarito and explanation from `/praticar/sessao`. Removing the literal is never enough on its own: git history is public forever, so the credential has to be **rotated**. Configuration reads go through `db.emails_admin()` / `db._database_url()` (secrets.toml, then env) or plain env vars, and the safe default is *no access*, never a working one.
